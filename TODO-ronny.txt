  Research Summary

  I've discovered the documentation is contradictory and describes multiple different operating modes. I've created
  a comprehensive analysis document at:

  E:\Dev\Ronny\RetroTerm\docs\TDV-ARROW-KEY-MODES-ANALYSIS.md

  What We Found:

  Three Different Modes Documented:

  1. TDV 2115 Compatible Mode (C0 codes, no modifiers documented)
    - Up=FS (0x1C), Down=VT (0x0B), Right=CAN (0x18), Left=BS (0x08)
    - Source: TDV 2215 official spec
  2. VT100 Emulation Mode (ESC sequences, no modifiers)
    - Up=ESC[A, Down=ESC[B, Right=ESC[C, Left=ESC[D
    - TDV-Keys.md says: "No support for ;2, ;5 modifier forms"
  3. VT220 Extended Mode (ESC sequences WITH modifiers)
    - Up=ESC[A, Shift+Up=ESC[1;2A, Ctrl+Up=ESC[1;5A
    - TDV-Keys.md says TDV 2200: "Modifier extensions (;2, ;3, ;5, etc.)"

  The Big Questions:

  1. Does "TDV 2115 compatible mode" support modifiers? - NOT DOCUMENTED
  2. Can C0 codes have modifiers? - NOT CLEAR (can you send "Shift+0x1C"?)
  3. What mode does each TDV model default to? - UNCLEAR
  4. What does SINTRAN actually expect? - We know C0 codes work for unmodified keys

  Our Current Implementation:

  Hybrid approach (not clearly documented anywhere):
  - Unmodified arrow keys → C0 codes (0x1C, 0x0B, 0x18, 0x08)
  - Modified arrow keys → ESC sequences (ESC[1;2A, ESC[1;5A)

  This works with SINTRAN, and all 86 tests pass. But we don't know if it's "correct" according to real hardware
  behavior.

  Recommendation: We need to either:
  1. Find more documentation about mode switching and modifier behavior
  2. Test with actual TDV hardware if available
  3. Keep current hybrid approach since it works with SINTRAN

TODO LATER - PUSH Key Programming (P1-P16)

Implement full PUSH key support: 16 programmable keys that send user-configured
strings to the host when pressed on the virtual keyboard.

## What exists already

- TDVPushKeys class (Core): basic Dict<int,string> storage with ProgramKey/GetKeySequence
- TDV2200KeyRegistry: G1-G8 registered with IsProgrammable flag, GetSequence returns null
- TDVDCSHandlerFeature: stub DCS handler (wrong format, parses "PUSH<digit><data>")
- TDV2200KeyboardMapper.MapKey: PUSH key path sends DCS "ESC P N|S {n} ESC \"
  (this is a query to the emulator, not the stored string — may need rethinking)
- TDV2200KeyLayout: G1-G8 as KeyType.PushKey with VK=0
- Virtual keyboard: PUSH keys are currently dead (no output on click)

## Spec summary (TDV-2200/9 User Guide + TDV2215 spec)

- 8 physical keys (G1-G8), 16 functions: P1-P8 (unshifted), P9-P16 (Shift+P1-P8)
- Capacity: P1-P8 = 12 chars, P9-P12 = 32 chars, P13-P16 = 48 chars
- Content: any bytes — ASCII text, ESC sequences, control codes
- Forbidden codes: 0x00 (terminator), 0xA0-0xAF (PUSH codes), 0xF8-0xFF (system)
- Storage: non-volatile on real hardware; we store in user settings (JSON)
- When pressed: sends the stored string directly to host, no prefix/wrapper
- Host can program via DCS: ESC P P XX <hex pairs> ESC \
  (XX = 01-16, hex pairs = ASCII hex for each byte, e.g. "1B" for ESC)

## Implementation plan

### Phase 1: Make PUSH keys send their stored strings

1. Virtual keyboard OnKeyPressed: when KeyType.PushKey, look up stored string
   from a PushKeyStore (new singleton or part of TDVKeyBindingConfiguration)
   - G1 unshifted → P1, G1 shifted → P9, etc.
   - Grid position "G1"-"G8" + shift flag → key number 1-16
   - If string is empty/not programmed, do nothing (or beep)
   - If string exists, send it via InputReceived

2. PushKeyStore: persistent JSON storage (%AppData%\RetroTerm\push-keys.json)
   - Dict<int, string> where key = 1-16, value = stored string
   - Load on startup, save on change
   - Max lengths enforced: P1-P8=12, P9-P12=32, P13-P16=48

3. Physical keyboard: Alt+1 through Alt+8 already bind to G1-G8 via
   TDVKeyBindingConfiguration._defaultAltMap. These go through the mapper
   which currently sends DCS. Change to: look up stored string and send directly.

### Phase 2: PUSH Key Programming Window

4. New window: PushKeyProgrammingWindow (Avalonia)
   - Grid/table showing all 16 keys: P1-P16
   - Columns: Key Number | Label | Max Length | Current Value | Hex View
   - Each row editable:
     a. Text input field for the string (shows printable chars, control codes as \xNN)
     b. Hex input mode (type hex pairs directly, like "1B5B35697E" for ESC[5i~)
     c. "Record" button: captures next N keystrokes as the string (like key capture mode)
     d. Clear button per key
   - "Clear All" button
   - Save/Cancel buttons
   - Show capacity used vs max (e.g. "5/12 chars")

5. Menu entry: Keyboard menu → "Program PUSH Keys..." opens the window

6. Virtual keyboard integration:
   - Show programmed indicator on PUSH key buttons (e.g. green dot or "P" icon)
   - Right-click PUSH key → opens programming window focused on that key
   - Show stored string preview in tooltip

### Phase 3: Host DCS Programming (receive from host)

7. Fix TDVDCSHandlerFeature to parse the correct DCS format:
   - DCS sequence: ESC P P XX <hex pairs> ST (where ST = ESC \)
   - Parse XX as two-digit decimal (01-16)
   - Parse remaining as pairs of ASCII hex digits → bytes
   - Store via PushKeyStore (same storage as user programming)
   - Reject forbidden codes: 0x00, 0xA0-0xAF, 0xF8-0xFF

8. Wire DCS handler through emulator → PushKeyStore:
   - TDVEmulatorBase.PushKeys already exists

### Phase 4: Polish

   - Or show "P1: DIR" if the string starts with "DIR"

10. Import/Export: allow saving/loading PUSH key configurations
    - JSON format compatible with PushKeyStore
    - Useful for sharing configurations between machines
