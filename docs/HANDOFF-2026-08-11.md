## 2. The three corpora — read this before touching any test

None of them is committed. They belong to other projects, they are fetched on demand, and the tests
pass cleanly when they are absent.

```powershell
tools\fetch-conformance-corpora.ps1
```

| Corpus | What it asserts | Where | State |
|---|---|---|---|
| **xterm.js** `escape_sequence_files` (MIT) | The **visible screen**, captured from a real xterm at 80x25 | `tests\RetroTerm.Tests\Conformance\xtermjs\` | 76 fixtures, **11 disagree, 46 rows** (was 61 / 879) |
| **libvterm** (MIT) | **Internal callbacks** — cursor position, damage rectangles, putglyph | `tests\RetroTerm.Tests\Conformance\libvterm\` | 43 scripts, **4 disagree, 9 assertions** (was 97) |
| **Tektronix** | Real gnuplot output streams | `tests\RetroTerm.Tests\Conformance\tektronix\` | 3 streams, clean |

**They catch different mistakes.** libvterm passes a screen that ends up wrong if the callbacks were
right along the way; xterm.js passes wrong intermediate state if the screen ends up right. Run both.

**How failures are handled.** Each has a baseline count per file. A regression pushes the count up
and fails; a fix pushes it down and *also* fails, telling you to lower the number deliberately.
Zero would be nicer; hiding disagreements behind a `Skip` would be worse than counting them in
public. Every number carries a comment saying what the debt actually is.

**`.gitattributes` marks all three `-text`.** Git offered to convert 154 line endings in the corpus
on the first commit. That would have silently changed the test data.

## 3. The trap that cost the most, and will catch you too

The fixtures were captured through a **tty with ONLCR on**, so a bare `\n` in a `.in` file arrived at
the real xterm as `\r\n`. Feeding the raw bytes made every full-width fixture step rightwards down
the screen, and I spent a tick hunting an 80-column bug that did not exist. `AsATtyWouldHaveDelivered`
in `XtermJsScreenTests.cs` inserts the CR. **The runner was wrong, not the emulator** — check the
harness before you believe a corpus.

The second-largest: **the two corpora genuinely disagree** about `CSI Pn k`. libvterm implements
ECMA-48's VPB; a real xterm ignores the sequence entirely. When they conflict, look for a third
source (here: `ctlseqs.txt` has no entry for `k`, and DEC's manual never mentions VPB) and record the
loser as a known disagreement **with the reason written down**.

The third: libvterm's `13state_edit` script carries its author's own note beside an assertion —
"ECMA-48 says we should move to line home, but neither xterm nor xfce4-terminal do this". I had
implemented the standard's wording. **Read the corpus's comments, not just its assertions.**

## 4. What the emulator gained

Grouped by what caused it. Every one of these has tests quoting the document behind it.

**From the xterm.js screens**
- The **Last Column Flag** (deferred wrap) — which operations disarm it is the single most
  productive source of defects in this codebase. LF, RI, IL, DL and a tab-with-nowhere-to-go all
  had it wrong.
- `SU`/`SD` (pan up/down) did not exist at all.
- `ED 3` erased the screen as well as the scrollback.
- A received CR fed a line under LNM, so every `CR LF` advanced two rows.
- An impossible `DECSTBM` (top ≥ bottom) reset to the full screen instead of being refused.
- Reverse wraparound (`DECSET 45`), including the undocumented part: from the top line it wraps to
  the **bottom** line.

**From the VT420 Programmer Reference**
- Page memory (`NP`/`PP`/`PPA`/`PPB`/`PPR`, `DECSLPP`), conformance levels (`DECSCL`), column
  editing (`DECIC`/`DECDC`, `SL`/`SR`), the rectangle family, left/right margins.

**Terminals added** — VT52 (with a VT100 that can drop into it), VT102, VT220, VT240, VT320, VT340,
VT420, xterm, xterm-256color. Plus Sixel, ReGIS, mouse reporting in both encodings, bracketed paste,
focus reporting, DECUDK and DECDLD soft fonts.

**UI defects Ronny found by eye, that tests should have caught** — the connection dialog listed
three terminals while the factory built thirteen; the language list had entries that did nothing.
Both are now generated from the single source. `CommandSurfaceEquivalenceTests` exists for exactly
this shape of bug and did not cover dialogs; that gap is now closed by
`TerminalTypeIsSelectableTests` and `ChosenTerminalReachesTheTabTests`.

## 5. Standing constraints — these are not negotiable

- **Clean room.** xterm, xterm.js, libvterm and vt340test are **specifications and oracles**. No
  line of their code is ported. Ronny's words: *"we can use xterm as specification for clean room
  development but do not ever port it."*
- **No LINQ, no `foreach`.** Indexed `for` loops, `Span<T>`, `ArrayPool<T>`.
- **No FluentAssertions.** xUnit `Assert.*` only.
- **Never mention Claude or AI in a commit message.**
- **Never kill a process you did not start.** Check `Win32_Process.CommandLine` first — most stray
  `dotnet.exe` on this box belong to RetroCore-spin, Unity or Visual Studio.
- **Comments stay.** Keep as many as possible; only replace one that is factually wrong.
- **Decisions go through AskUserQuestion**, never a paragraph ending in "your call".

## 6. The finishing routine, every time

```powershell
dotnet format RetroTerm.sln
dotnet build  RetroTerm.sln     # must be 0 warnings
dotnet test   RetroTerm.sln     # read the number, quote the number
dotnet build-server shutdown
Get-CimInstance Win32_Process -Filter "Name='dotnet.exe' OR Name='testhost.exe' OR Name='MSBuild.exe' OR Name='VBCSCompiler.exe'"
```

Step 4 is not tidiness. A leftover host holds the DLLs, the next build silently keeps the old
binary, and **the tests report green against stale code**.
