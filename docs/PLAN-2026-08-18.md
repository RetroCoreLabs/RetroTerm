### What P1 actually cost, and what it bought

The four write controls could not be built on the surface as it was, because **the surface stored a
colour per pixel and a VT340 does not**. Real pixel memory is four planes deep — a four-bit CODE per
pixel — and the output map turns that code into a colour as the screen is scanned. Every one of
these features is an operation on the code, not on the colour:

- the plane mask says which bits of the code a drawing may change,
- complement writing exclusive-ors those same bits,
- and changing the output map repaints the screen **without redrawing anything**.

So `InMemoryGraphicsSurface` now keeps the codes beside the pixels. Nothing else changed behaviour:
all 6016 tests that passed before still passed unchanged afterwards.

**Measured against the four hardware photographs**, sampling every second pixel:

| Drawing | Pixels agreeing with the real VT340 |
|---|---|
| checkerboard | 100.00% |
| raf | 99.85% |
| grid | 99.24% |
| bitplane | 73.99% — the whole shortfall is the emacs text on hackerb9's screen, which a graphics-plane dump does not have. Every colour sampled inside the picture matches |

**A find worth keeping:** the bitplane stream holds *two* ReGIS blocks, and `registest.sh` waits for
a keypress between them — `read -s -n1 -p "Magenta and green swapped. Hit any key..."` — so the
photograph shows the swapped palette and the second block is the undo. The comparison had been
reading to the LAST terminator, running the undo, and comparing a picture the camera never saw. It
now stops at the first. Two colours that looked like defects were this.

**One thing was wrong in P1.1 and is now fixed:** the pattern multiplier defaults to **2**, not 1.
The manual says so twice — "The default value is 2", and the note under figure 3-12 spells the
default write state out as `W(F3, N0, V, I0, P1(M2))`. Taken from the manual, NOT confirmed against
hardware: all four registest drawings give their multiplier explicitly, so none of them can tell the
difference. The maximum of 16 is now clamped too.

**Done means:** each of the four `compare-registest-*.png` sheets shows the same picture top and
bottom, allowing for the capture being a photograph. **All four now do.** What remains in P1 is
replace writing, which none of the four captures can judge.

**Why this is worth doing first:** it is the only work left in the program where an outside oracle
already says what the answer is. Everything else below is judged by a document, by Ronny, or not at
all.

## P3 — ReGIS `R`, the last command — **DONE 2026-08-18. ReGIS is ten of ten.**

Five of the six forms are built and answer with the exact bytes chapter 10 specifies: cursor
position, macrograph contents, macrograph storage, character set name and error condition. Each ends
with a carriage return, as "All information returned by the VT300 ends with a carriage return (CR)"
requires.

The decoder collects what it owes rather than raising an event — it owns no connection — and
`DrawRegis` sends it. `TheReportReachesTheHostThroughTheEmulator` drives a real VT340 with a device
control string and reads the bytes off the wire, so the whole path is covered and not just the
formatting.

**Two things deliberately left, both recorded in M6.4g:**

- **`R(E)` always answers `"0,0"`.** Nothing flags parse errors yet, so that is a truthful report of
  what this decoder knows. It is still sent, because a host that asks and hears nothing waits
  forever. Table 10-1's error codes remain unimplemented.
- **Graphics input mode** is the sixth thing chapter 10 covers and is not a report — it needs a
  pointing device. It stays counted, so a real host will say if anything uses it.

The macrograph total is **10,000 bytes**, from "The VT300 can store at least 10,000 bytes of
macrograph data" — the only figure the manual gives.

### What faketextcolor found

**Two gaps nobody had listed, both now built:**

1. **The pixel vector system was missing entirely.** Bare digits `0` to `7` are eight compass
   directions — `V0642` draws east, south, west, north — and `W(M n)` sets how many coordinates each
   step covers. The numbering came off figure 1-2, which OCRs as noise and had to be rendered and
   read; figure 1-3's five worked examples then pin it from the other side and are now tests.
2. **A space between arguments ended the argument list.** This stream writes
   `F(V(W(F1)) 0642)`, and the space before the digits stopped the loop — so the sixteen boxes drew
   nothing and only the `V0` separators appeared, as a thin line exactly sixteen steps long. The
   plane dump is what showed it; nothing failed.

Building the pattern multiplier's end index correctly fell out of the same work: the option scan
walks every character, so `W(P4(M2))` would otherwise meet that `M` and read it as PV multiplication.

**And one architectural limit, recorded rather than fixed** — see M6.4h. On a VT340 text and graphics
are the same four-plane bitmap, which is what lets ReGIS recolour text by clearing bitplanes under
it. Here text is a cell buffer and graphics are planes composited over it, so the same commands
cover the text instead of recolouring it. Making that work means drawing text into the graphics
bitmap, which touches selection, scrollback, fonts and rendering performance. **That is a decision,
and it belongs in P6.**

## The rules that have earned their place

- **Look at the pixels.** Six defects this month were invisible to every passing assertion:
  the doubled aspect ratio, red and blue swapped, plots in the wrong phosphor, `e` drawn as `c`,
  labels at half height, and a whole missing label.
- **When the thing being judged is smaller than the scaling, scale nothing.** Two artefacts lied
  before they were fixed — the Tektronix dash patterns and the Sixel comparison sheets — and both
  now dump the plane at one pixel to one pixel.
- **A fixture beats a document about which fixture matters.** The plan named `hersheydemo.regis` as
  the judge of the text command; it contains no text command at all. `registest.sh` does, and it
  came with captures.
- **Red before green**, and **clean-room only**: outside code is a specification to read and an
  oracle to run, never something to copy. Their files are fetched, never committed.
- **Finish with** `dotnet format` → `dotnet build` (0 warnings) → `dotnet test` (quote the number)
  → `dotnet build-server shutdown`, then check leftover hosts and their command lines before
  touching any of them.
